# 04 — Prompt Optimization Documentation

---

## 1. Goal

Shorten user prompts while preserving meaning, then measure token and carbon reduction.

Default production path: **local fine-tuned FLAN-T5-small** via `TrainedModelProvider`.

---

## 2. Dataset

### Source prompts
- File: `prompts_dataset.csv` (1,000 rows)
- Columns: `Prompt`, `prompt type`, `task type`, `token count of the prompt`

### Training pairs
- File: `prompt_optimization_dataset.csv` (10,000 rows)
- Columns: `original_prompt`, `optimized_prompt`
- Built by `build_optimization_dataset.py`:
  1. Wrap each base prompt in 10 verbose/politeness templates (`make_verbose`)
  2. Produce target via rule-based `optimize_prompt()` (regex de-verbosity; fallback to concise base)
- **Labels are synthetic**, not human or teacher-LLM annotations.

Split (training): 80/10/10 → 8000 / 1000 / 1000, `random_state=42`.

## 4. Training Pipeline

Script: `training/train_prompt_optimizer.py` (+ `training/config.py`, `run_training.sh`).

1. Load CSV → drop nulls → split
2. Load AutoTokenizer + AutoModelForSeq2SeqLM
3. Tokenize: input = prefix + original (max 128); labels = optimized (max 96)
4. `Seq2SeqTrainer` + `DataCollatorForSeq2Seq`
5. 3 epochs, batch 16, LR 3e-4, weight decay 0.01, warmup_ratio 0.06
6. Loss: cross-entropy (HF default), pad → -100
7. Optimizer/scheduler: AdamW + linear warmup/decay (HF defaults)
8. Eval/save each epoch; load best by `eval_loss`
9. Save to `models/greenprompt_model/`
10. Attempt ONNX export (no `onnx/` dir found — export likely failed silently)

**Actual run:** CPU, ~3.7 hours, train_loss ≈ 0.0249, best eval_loss ≈ 0.00159 at step 1500.

---

## 5. Tokenizer

T5 SentencePiece (`T5Tokenizer`), `model_max_length` 512, special tokens pad/eos/unk + `<extra_id_*>`.

Saved alongside model; inference reloads from model directory.

---

## 6. Inference Pipeline (Production)

`OptimizationService.optimize_prompt`:
1. Analyze original prompt
2. `PromptOptimizer.optimize_candidates` → provider
3. `TrainedModelProvider`:
   - Load tokenizer + model once
   - Encode `TASK_PREFIX + prompt`
   - Generate with **beam search**: `num_beams=5`, `num_return_sequences=5`, `max_new_tokens=96`, `early_stopping=True`, `no_repeat_ngram_size=3`
   - **Temperature:** unused (no sampling)
   - Deduplicate candidates; if empty → return original (no-op)
4. For each candidate: re-analyze, compute carbon, score via ranking engine
5. Reject if similarity &lt; threshold (default 0.50) or constraints broken
6. Build comparison with reduction formulas

**Note:** System prompt file is loaded for LLM API providers but **ignored** by `TrainedModelProvider` (prefix only).

---

## 7. Ranking Engine (Candidate Selection)

Not embeddings. Score components:
- SequenceMatcher ratio (65%) + Jaccard (35%), floor with content coverage × 0.6
- Token reduction component (clamped)
- Carbon reduction component
- Readability heuristic
- Penalties if task/prompt type changes

Constraint check: numeric literals and quoted strings from original must remain.

## 10. Semantic Preservation Assessment

- Soft check: similarity threshold 0.50 + constraint preservation
- Hard guarantee of meaning: **not formally proven** (no NLI/embeddings)
- Behavior learned: strip fillers like “Can you please…” — matches training distribution
- Already-concise prompts often unchanged (correct no-op)

---

## 11. Audit Verdict

Optimized prompts in default config are **generated by the trained model**, not random strings. Quality claims for a research paper must disclose **synthetic supervision** and **limited eval sample size**.
